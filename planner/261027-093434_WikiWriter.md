## Decisions (do not ask)

- Explicit stage tiers override the general cheap-first sentence: survey/organize/review start large, audit/cluster resolution/hubs start mid, other model items start small; a ceiling lowers any starting tier.
- The attempt ladder is small, small-with-errors, mid, large; mid starts get mid then large; large starts get one large attempt; ceiling removes higher attempts.
- Rate limits retry the same model at most 6 times after the initial call, waiting 1, 2, 4, 8, 16, 32 seconds; exhaustion leaves the item pending and ends scheduling for this run, never escalates.
- Each pair of rate-limit events halves active capacity, rounded down with minimum 1, for the rest of the run; in-flight work finishes.
- Other process failures, including timeout, get one retry at the same ladder slot before moving to the next higher tier; never take the small validation-repair slot for process failures.
- Timeout is 300 seconds per invocation; deterministic Fake clock/sleeper tests use no real waits.
- Codex read-only is containment, not proof that every tool is absent; disable tool features and external integrations explicitly, reject tool-call events, and never advertise stronger isolation than verified by the manual check.
- Use source-local page references plus monotonically numbered project page files; EPUB spine entries and text heading sections count as logical pages.
- Chunks target 20,000 Unicode characters, minimum target 16,000 and hard maximum 24,000; use PDF outline/EPUB TOC/text headings first and one whole-page overlap for fixed-window fallback where it fits.
- Pages with fewer than 40 non-whitespace characters are skipped and listed; oversized pages split into character slices at newline boundaries with no dropped text.
- Stable fact IDs are allocated by a persistent identity registry, not model output, and never recycled; unchanged facts keep IDs across redo and overlap.
- Audit samples deterministically select 10% rounded up (at least one when nonempty); always include escalated and table/stat-block chunks; failure rate strictly above 20% expands the current audit to 100% and persists that rate until extraction inputs change.
- Resolve uses same-type names/aliases with Jaro-Winkler >= 0.90; uncertain or non-clique positive clusters get a mid partition decision; no unsupported merge is allowed.
- Review samples at most 5 evenly spaced pages, queues only extract/write redo items for the next run, and never loops automatically in the same run.
- Budget is cumulative reported input+output tokens for the current run, including retries; running calls may overshoot; missing usage is charged by a character estimate and marked estimated.
- Token acceptance is saved against the ingest/config/prompt-version/ceiling fingerprint; `--yes` records acceptance; no interactive confirmation inside the driver.
- Default pipeline stops after review; rendering and installing are explicit. Blocked required global outputs skip their dependents with gap messages rather than fabricating schemas or outlines.
- New launcher interface is `wikify.sh <project> <sources...>` or `wikify.sh --project DIR` or no args inside a wiki; init does not automatically run the pipeline.
- Pin DokuWiki 2026-07-14c and the published tarball checksum below; failed verification must never unpack or replace an installation.
- Keep unrelated baseline test failures visible and unchanged; new WikiWriter gates require zero failures.

### Fixed implementation details

These details resolve underspecified edge cases. They apply to all phases.

- Target platform is macOS/Linux with a Unix shell, process groups, curl, tar and shasum. Homebrew installation is macOS-only; on other systems `make deps` prints which missing packages to install and exits 1. No Windows support is promised.
- Treat the planning baseline as historical evidence. Append the worker's baseline/final results in Implementation notes; never replace the historical counts. There is no need to rediscover conventions. Final registry verification reads only files created by this plan and root Makefile/README.
- The minimum Phase 1 pre-red crate is Cargo.toml with package name `wiki-writer`, version `0.1.0`, edition `2024`, the listed dependencies, an empty src/lib.rs, and tests/state.rs. Add main.rs at implementation time. An empty lib before the first red gate is test setup, not a shipped stub.
- All public data structs derive Debug, Clone, Serialize, Deserialize; enums additionally Copy, Eq, PartialEq, Ord, PartialOrd; integer/string-only structs additionally Eq and PartialEq. PageRef additionally Ord/PartialOrd ordered by source then page. Struct fields are required unless a default is explicitly given. Apply deny_unknown_fields to every persisted/config/agent-output struct. Enum YAML/JSON values are lowercase snake_case. Float-bearing structs derive only PartialEq. Use Stage's declared order, not alphabetic order, for reports.
- Config YAML is a mapping exactly matching Config fields. `version`, `project`, `agent`, and `sources` are required. `profile` defaults to `generic`; jobs/audit rates/timeout use the default table. `models` is an optional mapping with optional small/mid/large keys, filled from the selected provider's defaults; empty model strings are invalid. Fake fixture runs retain the saved real provider's model IDs while replacing transport only. All generated config fields are explicit. Config example: `models: {small: gpt-6-luna, mid: gpt-6.1-sol, large: gpt-6-astra}`. Source entries contain exactly id/name/path/sha256; path must equal `sources/<id>.<supported extension>`, sha256 is the init digest and is refreshed only by the ingest metadata, not rewritten into config on every run.
- Relative CLI source paths resolve against init's cwd; canonicalize each input, allow symlinks to regular readable files, reject duplicate canonical paths. Same basenames in different directories are allowed. `--project` may be relative to command cwd or absolute; canonicalize to an existing directory containing config. Once inside a project, generated paths must stay lexically within the canonical root and must have no symlink component; reject existing symlink output/config/state/source paths rather than following them. The immutable source manifest compares IDs, paths and order, not source content digests. Config project name must equal the saved name. Source name is the original basename (display only), never a path.
- State hash encoding is serde_json::to_vec of a tuple `(template_name, version, input_bytes, ceiling)`; SHA256 is lowercase hex. Upstream byte payloads are tuples/arrays serialized with serde_json and BTreeMap for keyed data. All model items include agent provider, complete Models mapping and profile in their input payload; deterministic items exclude these. Include stage-specific policy values (audit rates for audit; chunk constants for ingest); jobs, timeout, ledger and timestamps never invalidate semantic output. Explicit per-stage input lists below add to this common set. Resolved pair/cluster *input* hashes include supplied entities/facts and upstream decisions plus model config; their *output* bytes include verdict/groups/evidence and drive downstream hashes. "Evidence only" below means no unrelated project files, not omission of verdicts or config.
- `ItemRecord` gains `outputs: BTreeMap<String,String>` for relative output path→SHA256 when an item owns multiple files. For single-file tasks this map has one entry and output_path/output_hash mirror it. is_done verifies every entry. Ingest source records own `state/ingest/sources/<source>.json` containing that source's complete pages (including text) and TOC. Ingest/global owns all numbered page text files and merged pages/toc/chunks indexes; it remaps global file numbers in source order without re-running poppler for unchanged per-source extraction. Link/global owns only state/lint.json and stores final content input fingerprints separately in `state/link.json`; it never owns content as cached immutable output. Audit tasks own only correction JSON; effective/global owns effective notes files. Resolve/global owns entities.json; pair/cluster items have their own records. Render is governed only by render.json. Corrupt item records remain untouched until replaced after successful work; scheduler treats them pending and never trusts their outputs. A blocked item with unchanged input hash stays blocked until redo or an input/ceiling change; pending items retry on a later run. Blocked artifacts never count as current successful inputs.
- A fresh run ID is `<Unix epoch nanoseconds>-<process ID>`. Gaps are sorted unique strings `<stage>/<item>: <reason>`; append scanned gaps as `ingest/<source>: skipped page <N> (little text)`. Store current gaps in `state/gaps.json` as Vec<String>; pass canonical sorted gaps into dependent tasks. Error text may contain OS detail, but stable prefix/stage/item and exit codes are required. Human stdout uses plain text: stage table columns `stage done pending blocked escalation tokens dollars`, plus gap/scanned/redo lines. stderr contains `warning:` or `error:` followed by stage/item and reason. Tests assert semantic fields and explicit quoted messages, not spacing or OS-dependent wording.
- Item count is the number of expected items at the current stage, excluding helper global merge records when per-item work exists: ingest source count; survey 1; extract chunk count; audit selected chunk count; resolve candidate pairs + ambiguous clusters (0 if none); organize 1; write outline pages; link 1; review 1. Empty deterministic stages finish with valid empty outputs. Missing required global input means unknown pending count, never a fake blocked item.
- Numeric facts/fields remain strings; serde rejects JSON numeric values in string positions. Only config floats/cost require explicit finite checks. Grounding's non-whitespace count is Unicode scalar count. Citation syntax is exactly `\[\^f[0-9]{4,}\]` with the ID looked up; malformed citation-looking text is an error outside code (for example `[^f1]`). Canonical IDs have the minimum-width decimal allocation, so f00001 is not an alias for f0001.
- Fact identity is SHA256 of JSON tuple `(source, sorted unique PageRefs, normalized entity_type, normalized entity, normalized text, normalized quote, normalized fields map)`. Source is chunk.source; normalize map values, not keys. Fields belong to identity; aliases and table_like do not. Alias differences for the same identity are unioned/sorted and table_like ORed; retain lowest chunk ID as Fact.chunk. Registry stores the full identity tuple as well as its digest and detects a hypothetical digest collision by returning an error. Sort allocation by chunk ID then digest hex. Unchanged audit drafts are reidentified through this same registry; replacements that change identity get a new ID. `apply` intentionally returns drafts; caller assigns/reuses IDs and chunk. Never infer retained ID from replacement position.
- Exact normalized entity similarity means Unicode lowercase, collapsed whitespace, punctuation preserved (same normalization as grounding). Pair IDs contain two eNNNN IDs separated by a single underscore, so they cannot collide. A blocked pair creates no graph edge; keep its endpoints separate unless another fully supported clique/cluster decision merges them without contradicting a no edge. Failed/blocked cluster preserves every member separately. Page kinds impose no extra child/tree schema; hub navigation comes from the prompt and is checked by the same link validator. Start is an allowed unnamespaced exception only.
- Audit extraction fingerprint is SHA256 of sorted `(chunk ID, extract input_hash, raw notes output hash)` plus configured audit rate/threshold and audit template version. Configured policy changes therefore reset an expanded rate. Valid empty corrections are a successful audit with no failure. Audit expansion selects only successfully extracted chunks; blocked/pending extraction has no notes and is represented as a gap. Invalid audit after exhausted ladder is a failure in the rate denominator; transient/pending calls are excluded.
- Ledger budget uses actual usage when present; otherwise the character estimate. Add `usage_reported: bool` to Response and CallError so zero reported usage differs from missing usage; Fake fixture files must set it explicitly. At attempt completion, coordinator sets estimated_usage to !usage_reported and computes estimate once, without later reconciliation. No estimated reservations before dispatch: dispatch until capacity fills while cumulative completed charged tokens < limit, then wait for results. Budget 0 starts no calls. Retries require the same check. Errors with missing usage estimate input and captured text (possibly zero output).
- Parser streams feed coordinator events through channels while draining; this lets a tool event trigger immediate process-group termination. Ignore blank JSONL lines. Claude requires one final result; duplicate finals are BadOutput. Codex requires turn.completed after all completed messages; concatenate distinct item IDs once; duplicate same-ID messages are ignored, conflicting same-ID text is BadOutput. Missing final event/truncated JSON is BadOutput even with text. On timeout boundary first call try_wait: an already exited process wins; otherwise timeout kills. Output >8 MiB is killed, not silently truncated; error display is truncated to 4 KiB. Preserve reported usage parsed before failure.
- Acceptance includes every registered model template name/version, not prompt bodies. `--only` never consumes redo entries for other stages; forced predecessor redo means not current and causes an actionable prerequisite error. `--only extract` may use the successful ingest subset if ingest gaps were already recorded and a current schema exists. Other subset stages use the same explicit gap tolerance described below. Before scheduling a consumed redo queue item, atomically set its record pending with empty hash and add its force ID to `state/forced.json`; only then remove queue entry. Replaying that operation is harmless. On success atomically publish record then remove force ID. Restart with force still set may redo work once; never lose requested redo.
- Pre-extract estimates use N=number of successful chunks, P=N estimated pages, R=sum(max(source chunk count-1,0)) adjacent pairs, S=min(5,N). Resolve estimate is R*(400 input+100 output). Write estimate is P*(1500 input+1500 output). Survey input is actual constructed prompt chars/4 rounded up, output 1500; extract input is actual prompt chars/4 per chunk, output 1500 each; audit selected count uses policy sample plus mandatory chunks, input per selected chunk ceil(chars/4)+1500 and output 500; organize input 200*N/output 1500; review input 1500*min(5,P)/output 1000. Once entities/outline exist, use actual candidate/page counts and actual prompt sizes where materializable; no hypothetical adjacent pairs then. Zero eligible items estimate zero. Display these as estimates, not budget reservations.
- Markdown edits in content are always used by link/lint/review/render when the write draft is current. Lint may reject an edited page's broken references; do not silently rewrite it from the draft. A forced/input-changed writer run explicitly replaces content; docs must warn of that behavior. Review findings cite known IDs and nonempty reasons only; no extra evidence field exists. Review itself is cacheable; once-per-hash enqueue markers live in `state/review_enqueued.json` and are written after queue publication (duplicate queue entries are deduped on recovery).

State rules, in order:
1. Hash a serialized tuple of template name, explicit integer `version: N` header, input bytes, ceiling. Exclude remaining template text. Deterministic stages use their stage name and version 1.
2. Input bytes include sorted relevant config and upstream bytes. Never include ledger timestamps, elapsed times, render cache, or the entire project tree. Each later phase names exact upstream dependencies.
3. Write temp file with tempfile in destination directory, flush+sync, then rename and sync parent. Publish output first and item record last. On restart, orphan complete outputs without a matching record are recomputed safely. Corrupt records become pending with a warning.
4. Ledger is the sole append-oriented exception: serialize under one coordinator lock; ignore/truncate only an incomplete final JSONL line on restart. Earlier malformed lines are errors. This handles a kill mid-append.
5. Done requires output existence, stored input match and stored output hash match. A hash-changing redo alone must not force unchanged downstream output to regenerate.
6. New fact IDs use `state/fact_ids.json` mapping stable identity keys to IDs and a next counter. Identity key is the full tuple defined in Fixed implementation details: source ID, sorted unique page refs, normalized entity type/name/text/quote and normalized fields map. Normalize Unicode lowercase and collapse whitespace; do not erase punctuation. Reserve IDs atomically before notes publication. Allocation occurs sorted by chunk ID and fact identity, independent of completion order. Deleted keys remain reserved. Duplicate facts from overlap share one ID.
7. Persistent entity IDs use the smallest member fact ID with `f` replaced by `e`; no separately randomized registry.
8. Fake is internal: production clap accepts only claude/codex, config on disk rejects fake. Tests inject Fake through library APIs, never environment overrides in production.

Missing global schema/outline gives an actionable error. `--until` executes from ingest through named stage. They are mutually exclusive.
5. Budget check occurs before every actual invocation/retry on coordinator; cumulative spent >= limit stops new calls, leaving unscheduled items pending.
