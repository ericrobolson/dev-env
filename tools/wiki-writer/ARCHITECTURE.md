# WikiWriter architecture

`project.rs` initializes a staged project directory and immutable source ID/path manifest. `config.rs` validates the saved YAML. `ingest.rs` copies source text into source-local logical pages, TOC entries, and bounded chunks; Poppler extracts PDF text, lopdf reads PDF outlines, and zip/roxmltree read EPUB spine content. `state.rs` owns atomic writes, hashes, project locks, cache checks, path validation, and the persistent fact ID registry. `agent.rs` runs Claude or Codex through a temporary working directory and drains JSONL stdout/stderr while enforcing a timeout. `scheduler.rs` owns per-run concurrent calls, retries, capacity, budget charging, and the JSONL ledger. `pipeline.rs` coordinates survey, extraction, audit, resolution, organization, and the CLI run flow. `validate.rs` checks schema, grounding, outlines, citations, and links. `write.rs`, `link.rs`, `review.rs`, and `render.rs` own editable Markdown, deterministic links/lint, queued review findings, and protected DokuWiki pages.

Source records live in `state/items/ingest/` and own `state/ingest/sources/*.json`. The ingest merge owns numbered page text files and `pages.json`, `toc.json`, and `chunks.json`. Survey writes `state/schema.yaml`; extraction writes raw `state/notes/cNNNN.json`; audit writes correction JSON and effective notes; resolution writes pair/cluster decisions and `state/entities.json`; organization writes `state/outline.yaml`; writing owns immutable drafts in `state/drafts/` and publishes editable `content/` Markdown. `state/content_published.json` records the last machine-published content hash so writing, linking, and review retries preserve human edits. Link/lint writes `state/link.json` and `state/lint.json`. Review writes `state/review.json` and a deduplicated `state/redo_queue.json`. Rendering writes `dokuwiki/data/pages/*.txt` and `state/render.json`.

Each model task hash encodes its registered prompt name, integer version, relevant serialized upstream inputs and model/profile config, and the ceiling. Prompt body edits without a version bump do not invalidate output. Deterministic ingest hashes source bytes and chunk policy, without model settings. `ItemRecord.outputs` maps owned relative paths to SHA-256 hashes; a done cache hit requires matching input and output hashes. Outputs are written to a synced temporary file in the destination directory, renamed, then the record is published. Earlier malformed ledger lines are errors; an incomplete final JSONL line is truncated on recovery. The project lock prevents simultaneous mutating commands.

Fact IDs are monotonic `fNNNN` values allocated from a persistent registry keyed by the normalized identity tuple: source, sorted page references, entity type/name, text, quote, and field values. Aliases and table flags do not alter identity. IDs are never recycled; entities use the smallest member fact ID with `e` substituted for `f`. Audit corrections overlay raw notes and are grounded before they become effective notes. Failed audit items retain raw grounded facts. Review queues extract or write redo for the next run; it does not loop in the current run.

| Start and ceiling | Validation attempts | Process error | Rate limit |
|---|---|---|---|
| Small, large ceiling | small, small with errors, mid, large | one retry at same tier, then next tier | retry same model after 1, 2, 4, 8, 16, 32 seconds |
| Mid, large ceiling | mid, large | one retry at same tier, then large | same backoff |
| Large, large ceiling | one large attempt | one retry at large | same backoff |
| Any lower ceiling | remove tiers above ceiling | never exceed ceiling | exhaustion stays pending |

Each two rate-limit events halve dispatch capacity for the rest of that run, with a minimum of one. Backoff applies to the affected job; ready jobs continue to dispatch. The ledger records one row per actual attempt. Reported usage is charged when available; otherwise a character-based estimate is marked. The current run's completed charged tokens control dispatch, so already running calls may overshoot the budget.

`tests/fixtures/agent/` contains synthetic provider JSONL and Fake responses. Tests also build temporary PDF/EPUB/text projects and mock the DokuWiki installer tools. Run `cargo test --manifest-path tools/wiki-writer/Cargo.toml`, `bash tests/test-wikify.sh`, and `cargo fmt --manifest-path tools/wiki-writer/Cargo.toml --check`. Automated tests never call a paid model or download DokuWiki. Codex's read-only sandbox and disabled features are containment measures; they do not prove that every tool is unavailable. Tool-call events are rejected, and a live provider check is needed for the installed CLI.

The 2026-10-27 repository baseline had three unrelated `test-play-sound.sh` failures (9 passed, 3 failed); those legacy files were not changed. PHP was relinked, and `doctor` passed. A live Codex run on the 16-page Space Weirdos PDF completed survey, extraction, audit, resolution, organization, writing, linking, and review; the scanned cover was reported as a gap. The local DokuWiki release passed its pinned checksum, indexed all generated pages, and served index, article, and search pages over `127.0.0.1`; anonymous edits exposed read-only source. A direct edit of a rendered page survived rerender. The browser pane could not access the shell's localhost server, so visual browser navigation was not checked. Successful Codex calls passed the adapter's tool-event rejection, which is evidence for this run only.
